## 下载白名单

- 接口：`GET /workers`
- 正式服务地址：`https://shanhuai.top`，设备最终请求地址为 `https://shanhuai.top/workers`。
- `deviceId`：必传，对应山淮后台“考勤设备绑定”中厂家类型为 `弹厂家` 的设备序列号。未添加、已删除、厂家类型不匹配或序列号重复时拒绝查询。
- `productId`：可不传，默认值为 `1`。
- `update`：可不传。
  - 不传、空值或 `0`：返回项目内所有未删除且未退场的人员。
  - 秒级时间戳 `T`：返回 `T` 之后新增或修改的人员，以及 `T` 之后退场的人员；新增或修改返回 `del: "0"`，退场或删除返回 `del: "1"`。
- `data.del`：仅在增量查询中返回；全量查询不返回该字段。
- 增量删除数据来自数据库事务内生成的人员变更事件及删除快照；人员记录被物理删除后仍能返回稳定的 `workerId`、人员资料和 `del: "1"`，不是直接依赖当前人员表。
- 成功响应中的顶层 `time` 是本次同步游标，设备下一次增量查询应将该值作为 `update` 传回。
- 建议设备首次使用全量查询，之后每 30～60 秒使用上次响应的 `time` 做增量查询；不要持续使用 `update=0` 轮询全量数据。

## 查询人员接口补充字段

以下字段由 B 厂家查询人员接口实测返回，但当前厂家文档未列出：

- `workerId`：山淮系统人员 UUID，作为 B 厂家设备内稳定的人员编号，不是外部住建平台 ID。
- `userId`：该人员对应的镇海平台人员 ID。
- `workerCode`：该人员对应的宁波平台人员 ID（甬建码）。
- `jhWorkerCode`：该人员对应的金华平台人员 ID。
- 字段为 `null` 或空字符串时，表示该人员没有对应平台 ID。

该接口属于 B 厂家设备适配层，不属于镇海、宁波或金华平台接口适配层。

## 考勤照片上传

- 接口：`POST /photo`
- 正式请求地址：`https://shanhuai.top/photo`。
- 请求头 `ts`：必传，毫秒级时间戳。
- 请求体按厂家协议传 `base64`、`deviceId`、`fileName`、`workerId`、`time`、`direction` 等字段；`workerId` 使用 `/workers` 返回的山淮人员 UUID。
- `deviceId` 必须是后台已绑定的 `弹厂家` 设备，人员和设备必须属于同一项目。
- 图片上传至系统对象存储；考勤写入 `construction_attendance_records`，照片地址写入 `construction_attendance_record_photos`。
- 同一人员、设备及 `time` 重复上报时按同一条考勤幂等返回，不会重复生成考勤记录。

## 拉取补录考勤任务

- 接口：`GET /attendance-jobs`。
- 正式请求地址：`https://shanhuai.top/attendance-jobs`。
- 查询参数使用 camelCase：`deviceId` 必传，`productId` 可选且默认为 `1`，`update` 可选，`limit` 可选且默认为 `50`，范围为 `1` 到 `100`。
- `update` 为秒级时间游标：首次不传、传空值或传 `0`；后续传上次响应顶层的 `time`，只拉取该游标之后且已经到计划时间的任务。
- `deviceId` 按 `/workers` 相同规则精确解析，只允许后台有效且序列号唯一的 `B厂家` 设备。
- 只返回该设备绑定项目中、明确以该设备为目标、计划时间已经到达的补录任务。尚未到 `plannedAt` 的任务不会提前返回。
- 服务领取任务时使用数据库行锁和 5 分钟租约。同一任务在租约有效期内不会被重复领取；设备未回调且租约过期后可再次返回，重试时 `jobId` 和 `messageId` 保持不变，`attemptCount` 增加。
- 顶层 `time` 是本次任务游标，设备应保存并在下一次请求中作为 `update` 传回；租约过期的重试任务不受 `update` 限制。
- 成功响应示例：

```json
{
  "success": true,
  "code": 0,
  "message": "success",
  "time": 1785897600,
  "event": "attendanceJobs",
  "data": [
    {
      "jobId": "3fe80766-9851-4a68-b270-c70ec229597d",
      "messageId": "supplemental-attendance:记录UUID:设备UUID",
      "projectId": "项目UUID",
      "workerId": "人员UUID",
      "workerName": "张三",
      "attendanceTime": 1785897600000,
      "direction": "in",
      "photoUrl": "https://example.test/photo.jpg",
      "attemptCount": 1
    }
  ]
}
```

- `attendanceTime` 为毫秒级时间戳；`direction` 仅为 `in` 或 `out`；没有照片时 `photoUrl` 为 `null`。

## 上报补录考勤结果

- 接口：`POST /attendance-results`。
- 正式请求地址：`https://shanhuai.top/attendance-results`。
- 请求体使用 camelCase。`deviceId` 必传，`productId` 可选且默认为协议值 `1`；`data` 可以是一条结果对象或结果数组，每次最多 100 条。
- 每条结果必须传 `jobId`，并至少通过 `status`、`success` 或 `code` 表达结果；可选传 `msg`/`message` 和 `time`。`time` 支持秒级时间戳、毫秒级时间戳或 RFC3339 时间。
- 状态归一规则：`accepted`、`processing`、`pending` 记为 `accepted`；`success`、`ok`、`0` 或 `success: true` 记为 `success`；`failed`、`error`、非零数字或 `success: false` 记为 `failed`。
- 设备只能回调属于自己 `deviceId` 的任务，否则返回 404。收到合法回调后，平台投递状态记为 `delivered`，设备处理状态单独保存。
- 状态转换支持设备先返回 `accepted`，之后再返回 `success` 或 `failed`；`failed` 后允许纠正为 `success`；`success` 为终态，后续 `accepted` 或 `failed` 不会将其降级。
- 完全相同的重复回调返回 200 并按重复事件留痕；被终态规则忽略的回调也返回 200，响应 `status` 是数据库中实际生效的状态。
- 请求与响应示例：

```json
{
  "deviceId": "B-DEVICE-001",
  "productId": 1,
  "data": [
    {
      "jobId": "3fe80766-9851-4a68-b270-c70ec229597d",
      "status": "success",
      "code": 0,
      "message": "补录成功",
      "time": 1785897600000
    }
  ]
}
```

```json
{
  "success": true,
  "code": 0,
  "message": "success",
  "time": 1785897600,
  "event": "attendanceResults",
  "data": [
    {
      "jobId": "3fe80766-9851-4a68-b270-c70ec229597d",
      "status": "success"
    }
  ]
}
```
